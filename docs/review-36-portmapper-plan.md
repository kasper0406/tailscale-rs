## Findings by severity

### High

1. **An old create/renew can resurrect a mapping after rebind, disable or close.** `P:312–315` specifies a mutex and single-flight flag, but no transaction generation or cancellation protocol. An attempt can snapshot port A/gateway A, await a reply, then install it after `set_local_port`, network invalidation or `close`. Releasing only the currently installed mapping also misses an in-flight request already applied by the router. `R/ts_runtime/src/direct.rs:384`, `:422`, `:461` are separate entry points; the plan omits the bare `rebind` handler from its explicit wiring.

   **Fix:** serialize transitions under one state lock; snapshot a generation including gateway, source IP, interface and local port. Increment it on invalidation/disable/close; cancel old work and reject stale commits and probe-cache updates. Keep enough pending-request identity for bounded best-effort cleanup. Close must prevent new work before awaiting, drain/stop workers, then release. Reset single-flight on every completion, panic and cancellation path; reap completed `JoinSet` entries. Give `Runtime` a synchronous cleanup handle: today it holds only `ActorRef<DirectManager>` (`R/ts_runtime/src/lib.rs:88–94`), which cannot service an async request from `Drop`. Keep release within the caller's total shutdown timeout (`:1475–1501`), rather than adding an unconditional second before it.

2. **The proposed renewal timer can produce a mapping storm.** `P:421` sleeps until the mapping's fixed `renew_after`. After a failed renewal that time remains in the past, so the branch is immediately ready again; single-flight limits concurrency, not attempts per second. Short/zero lifetimes and repeated kicks aggravate this. Conversely, no unconditional expiry timer exists: once the raw address is copied into magicsock, it can remain advertised after expiry while periodic work is idle/peerless.

   **Fix:** distinguish `next_attempt_at` from lease renewal/expiry, enforce retry spacing across *all* triggers, and advance it after failures. Respect bounded PCP error retry lifetimes. Schedule expiry independently of activity/peer count; store expiry/generation with the advertised address or read a current client snapshot. Publish loss/disable/expiry as well as success. Use one atomic state snapshot for endpoint and `HavePortMap`. A `watch` channel carries latest state and can coalesce changes; it cannot promise “exactly once” events. [RFC 6887 §§11.2.1, 11.4](https://www.rfc-editor.org/rfc/rfc6887.html#section-11.2.1) also specifies renewal spacing and error cooldowns.

3. **“LAN only” is an intention, not yet a complete security boundary.** `P:332–335` pins the root-description connection but does not specify resolution of XML `URLBase`, absolute/relative `controlURL`, changed service ports, or HTTP redirects. A malicious SSDP/XML responder can otherwise turn SOAP or a redirect into an internet/other-LAN request. Pinning only `Location` is insufficient. Even a private gateway address is not proof of an on-link destination; a VPN route can carry RFC1918 traffic remotely. Binding a source IP does not bind unicast traffic to an interface or prove that the interface is still present.

   **Fix:** construct a validated gateway/interface capability once per generation. Every TCP connect, including SOAP/delete, must pass through it; pin/revalidate resolved service URLs, forbid redirects (or validate every hop), DNS, proxies, userinfo and non-HTTP schemes. Permit legitimate service ports explicitly. Validate on-link route/interface/source ownership, and scope multicast to that interface with TTL 1. Test malicious `URLBase`, absolute control URLs and redirects with a separate listener proving **zero connections**. Pinning still permits attacker-directed requests to arbitrary gateway ports/paths: document this residual LAN attack surface. Bound headers, decoded chunked bodies, XML depth/node count, service count and the whole attempt deadline; reject DTD/entities with a real XML parser. Prefer the existing HTTP/1 transport over a new parser (`R/ts_http_util/src/http1.rs:71`); error-level logging is a smaller problem than implementing framing correctly.

4. **Router-state bounds are overstated, particularly for permanent UPnP.** `P:710–712` claims PMP/PCP expire within two hours and permanent UPnP leaks one rule per crash. Go trusts returned PMP/PCP lifetimes (`G/net/portmapper/portmapper.go:764`, `pcp.go:149`); PCP may legitimately grant *longer* than requested ([RFC 6887 §15](https://www.rfc-editor.org/rfc/rfc6887.html#section-15)). A successful permanent Add whose HTTP reply is lost can leak a new random-port rule on every retry, without any crash. Checking external IP before Add correctly fixes one leak class, not ambiguous Add completion. Persisting only the last returned external port cannot recover a rule whose response never arrived.

   **Fix:** state the bound as the **granted router lifetime**; cap local trust/renewal intervals without claiming that changes router expiry. Retain mapping ownership until cleanup, including rejected advertisements. For permanent UPnP, require an explicit supported policy: finite leases by default with permanent fallback opt-in, or stable/persisted request identity and ownership-aware recovery before retry. Never delete a persisted port blindly on a different router. Test lost Add responses and repeated restarts, and bound outstanding mappings, not just tasks. Do not defer this decision until after phase 2 ships.

### Medium

5. **Gateway lookup needs a more precise contract.** Go's Linux heuristic does **not** require a default route: it takes the first UP+GATEWAY route with a private gateway (`G/net/netmon/interfaces_linux.go:73–88`), without checking destination, mask or metric. Copying that can choose a private static-route/VPN gateway. The macOS approach is feasible but needs checked `rtm_msglen`, version/header lengths, sockaddr alignment/length handling (including compact masks), bounded allocation/sysctl resize retries and safe reads rather than casting arbitrary byte buffers. Go uses `x/net/route`, not an equivalent small hand-written parser (`interfaces_darwin.go:19–25`, `interfaces_bsd.go:74–106`).

   **Fix:** define default-route/mask/flags/metric selection, retain interface index, select an address on that up interface whose prefix contains the gateway, and reject ambiguous/unreachable results. Add multi-route, overlapping-subnet, VPN and interface-disappearance fixtures. Return `Result<Option<Gateway>, Error>` so permission/parser errors remain diagnosable. The proposed `Option<(Ipv4Addr, Ipv4Addr)>` cannot represent the IPv6 gateway needed by case 14/`GatewayIpv6`; either remove that unreachable API case or use a typed lookup result before IPv4 validation. Test-only loopback transport must be distinct from production validation, including the manual override.

6. **No netmon means stale-network detection is unbounded by the claimed ~23 seconds.** `R/ts_runtime/src/lib.rs:455–462` really uses `NoopLinkMonitor`, only when enabled. The planned periodic gateway check is gated by activity (`P:419`); an idle mapping may not check again until hourly renewal, and an idle unmapped node may not check at all. Two networks can also have identical gateway/self addresses. Keeping the mapped address through every rebind (`P:362`) worsens this, including a failed rebind leaving no bound socket (`R/ts_magicsock/src/sock.rs:723–733`). Sending a delete to a stored private gateway IP after moving networks can reach a different router.

   **Fix:** invalidate synchronously on every explicit rebind/network-down and failed socket replacement; compare interface/network generation, not just two IPs. Use a bounded lightweight route/interface poll independent of the STUN idle gate until OS monitoring exists. Skip cleanup when the old network cannot be identified/reached safely. Immediate advertiser notification and expiry checks must remove stale endpoints even while idle.

7. **Endpoint ordering and STUN evidence need explicit reconciliation.** `self_endpoints()` can put the mapping first, but `R/ts_runtime/src/direct.rs:984–985` then sorts by address/type. It also currently permits the same address to appear with different types. Go deduplicates by address, with portmapped winning (`G/wgengine/magicsock/magicsock.go:1315–1337`). If Rust adopts that deduplication, its current `WorkingUDP`/mapping-varies functions lose STUN evidence when STUN and the mapping share an address (`R/ts_control/src/tokio/client.rs:534–560`).

   **Fix:** preserve explicit endpoint priority through publication, deduplicate by address, and carry STUN-derived facts independently of presentation types. Keep a portmap-only endpoint from manufacturing STUN success. Test identical STUN/portmapped addresses, unchanged external address on renewal, port changes, and loss-only reports. The CallMeMaybe gate change at `R/ts_runtime/src/direct.rs:1035–1041` is necessary and correctly identified.

8. **Live disable semantics and packet validation are underspecified.** Reading atomics only at attempt start does not stop an in-flight UDP/SOAP send or remove a cached mapping. In particular, `only-tcp-443` must gate the mapper's own I/O, including Drop/delete traffic (`R/ts_control/src/node.rs:818–829`), rather than relying on magicsock's separate gate. PCP nonce matching alone is insufficient; validate reply bit/opcode, UDP protocol and internal port, source gateway/port and generation. Check PMP internal port too. Go omits several of these checks (`G/net/portmapper/pcp.go:128–157`, `portmapper.go:751–768`); copying omissions is unnecessary.

   **Fix:** define separate policies for disable-all versus disabling UPnP, invalidate/cancel immediately, and apply policy at each send/commit. For `only-tcp-443`, prefer no further LAN packets and let existing leases expire; make that cleanup tradeoff explicit. Generate PCP nonces with a cryptographic RNG. Reject local port zero before creating any mapping: in PCP it can request an all-ports mapping. Keep returned external-port validation protocol-specific; zero must never become an endpoint or UPnP delete target. Treat spoofed replies as untrusted discovery data, never authority to choose an arbitrary internal target.

### Router safety and LAN attackers

Normal state is one inbound UDP translation/pinhole, `external address:assigned port → self IP:actual underlay port`, open to arbitrary source hosts. It is not a TCP rule or an exit/subnet route. WireGuard/disco authentication still protects overlay traffic, but the exposed UDP listener receives unsolicited internet traffic and can be flooded. Renewals should update this one rule; port changes/protocol switches must retain cleanup ownership of old rules.

Crashes, SIGKILL and power loss cannot execute Drop. Finite rules survive for their granted lifetime; permanent ones can survive indefinitely, and a later DHCP assignee could inherit their target address. Home-router safeguards are partially present (UDP only, nonzero internal port needed, bounded requests, UPnP port floor, pre-Add validation), but findings 1–4 are required to bound stale work and leaks. Never issue wildcard deletes or overwrite unrelated rules to resolve conflicts.

PMP and SSDP are unauthenticated; source filtering impedes stray/off-path packets, not an on-LAN spoofer. PCP nonce checking helps off-path spoof resistance, not an observer who sees requests. Attackers can fabricate service availability, force failures/churn, offer malicious XML, or supply a false external IP that becomes a peer ping target. Bound packet/parse work and logs, preserve absolute deadlines under junk floods, and keep mapping targets fixed to the selected host/socket. Endpoint validation cannot authenticate the router or prove internet reachability.

### macOS deployment and phase 0

**Expected: no Local Network prompt for this system daemon, despite `UserName`.** Apple's current [TN3179 macOS guidance](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy?changes=__3) exempts launchd daemons independently of its root-process exemption, while explicitly excluding launchd agents. It also says macOS does not require the multicast entitlement. The plist is installed under `/Library/LaunchDaemons` and bootstrapped into `system` (`deploy/launchd/install.sh:12`, `:46–50`); `UserName` changes credentials, not that launch domain. Thus UDP gateway access and SSDP should be allowed. This is an inference from current documented policy, not a kmini measurement.

There is historical uncertainty worth testing: [Apple DTS's July 2024 beta discussion](https://developer.apple.com/forums/thread/759955) specifically asked whether `UserName` was used, and its successful example did not establish this exact wrapper/user arrangement. Terminal/SSH success is insufficient evidence because those contexts have their own exemption.

Phase 0 should record OS/build, launch domain, effective UID, executable identity, selected interface/gateway/source, send errors **and received responses**. Force PMP and PCP separately, then exercise source-bound multicast/unicast SSDP and eventually HTTP/SOAP. Confirm a nonzero assigned port, usable external address, router-table entry, inbound reachability from outside, and deletion/table removal. Exercise before-login boot, route-not-ready retry and sleep/wake. Preserve `EPERM`/`EHOSTUNREACH` diagnostics instead of relabeling every failure “no services.” Use a dedicated bound test port, avoid the running node's mapping/identity, and a one-shot system job with the same user/wrapper context: the production plist has `KeepAlive=true` (`:27–30`), so dropping probe mode directly into it would repeatedly rerun it. This review did not launch that probe.

### Phasing and effort

Phases 0–1 are sufficient **conditionally**: successful PMP or PCP must create a useful inbound mapping, and the café/client UDP path must allow reaching it. `MappingVariesByDestIP=true` characterizes mapping, not filtering or guaranteed UDP reachability; the motivation's explanation of the home router's filtering is a hypothesis. UPnP matters if PxP discovery succeeds but mapping is refused/unusable. Require either protocol to pass phase 0; requiring both `PMP=true PCP=true` adds no assurance that either MAP works. Use the Go node under the same network conditions as a comparison, not a guarantee.
