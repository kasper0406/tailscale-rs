## Ranked blockers / acceptance gates

1. **Security: residential egress lacks Go's destination boundary.** `HostExitDialer` ignores `FlowClass` and connects TCP/UDP to the supplied address without a forbidden-destination check (`F/ts_forwarder/src/dialer.rs:143`, `:156`). Default-route classification covers private, loopback and CGNAT destinations (`F/ts_forwarder/src/class.rs:41`). Only **ProxyExitDialer** applies `exit_dst_is_forbidden` (`F/ts_forwarder/src/dialer.rs:277`, `:314`). Therefore an ACL-admitted exit peer can drive host sockets into the Mac's LAN, loopback services, and any other tailnet IP reachable through the Mac's host routing table. This is conditional on the effective ACL matching that destination, not an unconditional bypass of every ACL. The existing passing HostExit test actually forwards a default-route flow to **127.0.0.1** (`F/ts_forwarder/tests/forwarding.rs:31`, `:437`). Add a destination boundary before socket creation, with separately authorized explicit subnet routes; test with the real control-produced `autogroup:internet` rules. A private test tailnet alone does not fix this.

2. **Security: changing/expiring a peer key does not invalidate existing WireGuard sessions.** `Endpoint::upsert_peer` changes the node-key index/config but retains the peer's session and pending handshake (`F/ts_tunnel/src/endpoint.rs:1028`). `IdMap::remove_peer` removes only the node-key entry (`:347`); data packets resolve by session ID (`:1188`) and decrypt using the retained session (`:664`). Expiry rewrites the node key, clears endpoints/DERP home, but retains the node and routes (`F/ts_control/src/expiry.rs:259`); source-route installation does not check `expired` (`F/ts_control/src/node.rs:494`). **Static inference:** if old-session packets still reach the direct underlay, a now-expired/replaced identity can continue ACL-admitted egress until session expiry, potentially the remainder of the 180-second receive-key lifetime (`F/ts_tunnel/src/session.rs:32`, `:378`). Full peer deletion does call `shutdown` (`F/ts_tunnel/src/endpoint.rs:1074`), so deletion differs from key replacement. Reset sessions/handshakes on key changes and explicitly refuse expired peers; require an established-session expiry/replacement regression test. This was not exercised by the forwarder-only tests.

3. **Functional: IPv4-only advertisement is incompatible with the pinned Go exit-node selection contract.** Fork `advertised_routes()` strips all IPv6 routes and adds only `0.0.0.0/0`, even with `enable_ipv6=true` (`F/ts_control/src/config.rs:673`). Go sets `PeerStatus.ExitNodeOption` using `ContainsExitRoutes` (`G/ipn/ipnlocal/local.go:1680`), which requires **both** `0.0.0.0/0` and `::/0` (`G/net/tsaddr/tsaddr.go:185`). Expect the Rust node to be absent from the normal official client exit selector. Exact installed iPad behavior remains an on-device gate; the pinned shared Go backend supplies strong evidence, not a completed iPad test. **Disagree with PLAN Phase 1.7:** “do not advertise ::/0 until working” conflicts with the official-client MVP. Implement IPv6 egress, or advertise the required pair with an explicit, tested IPv6 reject/blackhole policy and document that limitation. Merely widening advertisement without controlling IPv6 packets is insufficient; deliberate rejection should let browsers fall back to IPv4 promptly and prevent IPv6 escape.

4. **Functional: daemon advertisement does not enable forwarding.** Public fork flags `advertise_exit_node`, `forward_exit_egress`, and `forward_all_ports` are independent, all default false; explicit port sets default empty (`F/src/config.rs:118`, `:143`, `:155`, `:709`). The daemon only assigns advertisement/routes (`D/src/ipn/config.rs:88`, `:104`), never host egress or all-port mode. It consequently selects `DirectDialer` and has no forwarding listeners. Configure all three in a purpose-built runner after the security fixes; toggling advertisement later does not change the startup-selected dialer or port mode.

5. **Security gate: control updates can be lost, leaving stale authorization.** Runtime uses `MessageBus::spawn_default()` (`F/ts_runtime/src/env.rs:451`); packet-filter/source/route/peer changes reach dataplane via separate bus subscriptions (`F/ts_runtime/src/dataplane.rs:281`). The default bus delivers best effort, without replay (verified in dependency `kameo_actors-0.4.0/src/lib.rs:41` and `src/message_bus.rs:195` under `/Users/knielsen/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/`); the fork itself identifies this failure mode at `F/ts_runtime/src/packetfilter.rs:86`. Actual filter publication is a bus publish (`:315`), and dataplane retains the previous filter until a delivered update (`F/ts_runtime/src/dataplane.rs:344`). A missed restriction/revocation is therefore a stale **allow**, not necessarily a safe refusal. Make security snapshots reliable and apply peer/source/filter/route state coherently; test revocation during saturation before advertising on a real tailnet.

DNS does not categorically block the first IPv4 demo: the public API lacks a peerAPI DNS listener, but Go has an older-exit fallback through configured/fallback resolvers. Verify that path with the official iPad rather than treating the fork's DoH implementation as wired and working.

## Policy semantics and other security risks

**Go is more than an ACL matcher.** Its inbound filter checks a local destination set before normal protocol ACL handling (`G/wgengine/filter/filter.go:502`). Exit routes are shrunk by interface routes and `removeFromDefaultRoute`, excluding RFC1918, link-local, multicast and Tailscale ranges; explicit advertised subnets are added separately (`G/ipn/ipnlocal/local.go:3463`, `:3602`, `:3704`). Fork has no equivalent boundary: control's `/0` routes directly to the forwarder. Do not assume `autogroup:internet` compilation alone supplies Go's LAN isolation, or confuse a client's “allow LAN access” preference with permission to access the exit Mac's LAN.

**Loopback nuance:** Go's shrink operation re-adds host interface IPs before fixed exclusions (`G/ipn/ipnlocal/local.go:3717`); `interfaceRoutes` does not explicitly exclude loopback interfaces (`:3682`; `G/net/netmon/state.go:195`). Consequently this pinned code does **not** justify a universal claim that Go forbids every loopback/host IP under every policy. The fork's demonstrated arbitrary loopback dial remains a clear exposure. For the isolated experiment, forbid loopback/link-local/CGNAT and attached LAN destinations unless separately intended; that can be stricter than Go's host-IP exceptions.

**Existing-flow revocation is not immediate:** non-SYN TCP passes without ACL matching (`F/ts_dataplane/src/lib.rs:641`), matching Go's design (`G/wgengine/filter/filter.go:523`). UDP forwarded replies create reverse admission-cache entries, and cache hits bypass subsequent ACL checks (`F/ts_dataplane/src/lib.rs:608`; flow insertion `F/ts_dataplane/src/flowtrack.rs:86`). This cache is a 512-entry LRU with no time TTL (`:67`, `:137`); flow NAT expiry does not flush it. After ACL revocation, an old tuple may start another UDP mapping while cached. Document parity rather than promising immediate per-packet revocation; deletion/expiry should still invalidate identity reliably.

**Live advertisement is not retained:** `set_routable_ips` only sends a command (`F/ts_control/src/tokio/client.rs:236`); its handler sends the supplied routes without updating the frozen config (`:883`). Subsequent endpoint/home-region/hostname reports and reconnects send startup `config.advertised_routes()` again (`:871`, `:849`, `:914`, `:753`). A live withdrawal or enable can thus be undone on the wire while the local forwarder table retains the new setting. Carry the effective advertised routes across all reports/reconnects before relying on `set_advertise_exit_node` for startup gating or rollback.

**SYN memory exposure:** all-port limits accepted splices to 2048, but that permit is acquired only after accept (`F/ts_forwarder/src/tcp.rs:55`). Each of up to 1024 listeners has 128 pending sockets, created with eager 2 × 256 KiB buffers (`F/ts_netstack_smoltcp_core/src/config.rs:97`, `:101`; `F/ts_netstack_smoltcp_core/src/socket_impl/tcp/mod.rs:35`; listener promotion/replacement `F/ts_netstack_smoltcp_core/src/socket_impl/tcp/listener.rs:298`, `:334`). The configured theoretical pending-buffer envelope is approximately **64 GiB**, plus ~512 MiB for idle listeners and accepted flows—not the documented ~1 GiB global-splice envelope. An ACL-authorized peer can exhaust a Mac far below that limit without forging its source. Budget sockets/bytes globally **before SYN allocation**, use small handshake buffers, and limit ports/per-peer state.

## Performance / transport seams

**All-port mode is opt-in, not automatic for exit nodes.** `forward_exit_egress=false` → `DirectDialer` (subnets only); true + `exit_proxy=None` → `HostExitDialer`; true + proxy → `ProxyExitDialer` (`F/ts_runtime/src/forwarder_actor.rs:85`). `forward_all_ports` independently selects `Forwarder::all_ports` and ignores explicit port lists (`:52`). Both selections happen at startup. The public API exposes these fields and forwards them (`F/src/config.rs:659`); no hand-built dialer injection is necessary. Proxy TCP is fail-closed; proxy UDP is unsupported and never falls back (`F/ts_forwarder/src/dialer.rs:334`). Use **no proxy** for home-ISP egress.

**Cold SYN cost is per destination port across the forwarder, not per hostname/IP/connection.** Raw observer consumes a copy, suppresses unmatched RST, then asynchronously opens a listener; it never reinjects the first packet (`F/ts_forwarder/src/all_port.rs:109`, `:127`, `:146`). If several connections arrive before the listener is ready, all can lose their first SYN. With the task's ~1s initial client RTO assumption, a cold HTTPS page incurs roughly **+1s on its critical path**, not 1s × every HTTPS origin. Example: 20 parallel new :443 connections all race listener creation → as many as 20 retransmitted SYNs / 20 connection-seconds waiting, typically ~1s wall delay. HTTP :80 redirect followed by cold :443 → roughly +2s serial delay. Warm same-port connections avoid this penalty.

TCP port “last activity” is refreshed **only by SYNs** because non-SYN packets are discarded before timestamp update (`F/ts_forwarder/src/all_port.rs:129`, `:247`). Listener eviction happens after 120–180s without a new SYN, even during established streaming (`:165`); active detached splices can continue, but the next new connection pays the cold-port penalty again. UDP timestamps do refresh for every observed datagram (`:201`). Cold UDP :443 loses a QUIC Initial and pays its client-specific probe timeout; cold :53 loses a DNS query and can delay all dependent web requests. These are predicted effects, not iPad measurements.

**Fix:** first pre-open TCP 80/443 and UDP 443 plus TCP/UDP 53, retaining dynamic support for other ports. Current `forward_all_ports=true` ignores configured port lists, so this requires a small manager change with a listener-readiness barrier; setting both options does not prewarm anything. Pin these listeners against eviction. Correct general fix: add a synchronous unmatched-flow hook to smoltcp dispatch (or classify/register listeners before iface ingress), preserving the original SYN/datagram and processing it exactly once after listener creation. Bound pending packets and do not replay every raw copy—warm traffic is also observed. Preserve ACL/source checks before dispatch. This is an intentional-loss correctness/latency fix appropriate to Phase 1, despite the plan's broad “no performance patching yet” rule.

**Fork direct UDP is real.** Runtime starts `DirectManager`; confirmed paths override DERP, otherwise DERP is retained (`F/ts_runtime/src/lib.rs:223`; `F/ts_runtime/src/route_updater.rs:350`). On macOS, default magicsock uses **one shared, unconnected Tokio UDP socket bound to `0.0.0.0:<configured-port-or-ephemeral>`**, carrying WireGuard/disco/STUN; optional v6 tries one `[::]` socket with IPv4 fallback (`F/ts_runtime/src/direct.rs:233`, `:244`; `F/ts_magicsock/src/sock.rs:385`). `send_to` per packet (`:441`), `recv_from` per packet (`:1346`); no Darwin `sendmsg_x`/`recvmsg_x` batching or connected per-peer socket pool here. No explicit `IPV6_V6ONLY` setting is made. A read-only raw socket probe on this machine returned **0** for an IPv6 wildcard UDP socket, contradicting the source comment that macOS defaults to v6-only (`F/ts_runtime/src/direct.rs:220`); test actual Tokio v4-mapped send/receive if enabling v6. Do not confuse this with the forwarder's **connected** per-flow UDP egress sockets. Path availability still needs a real direct-vs-DERP observation.

**Rebind receive stall:** `rebind` swaps the stored Arc but does not cancel/notify a pending receive (`F/ts_magicsock/src/sock.rs:505`); that receive holds its own Arc to the old socket (`:1346`). Dropping the stored Arc cannot close the socket while that future owns it, contrary to the comment at `:503`. At an idle link change, receive can remain parked on the old port while STUN/pings use the new one. The runtime select may cancel/restart it when direct outbound traffic wins (`F/ts_runtime/src/direct.rs:641`, `:661`), or a packet on the old socket can release it; this is **not guaranteed recovery** after a disconnect. Use a socket-generation watch/Notify to cancel and restart receive, and test a rebind with a pending recv and no old-port traffic.

**Official comparison: do not describe b44db0da as DERP-only.** It has no separate `ts_magicsock` crate, but equivalent components: `DirectActor` binds separate shared v4/v6 UDP sockets (`O/crates/ts_runtime/src/direct.rs:115`, `:121`), disco/path-discovery modules, and best-path selection ahead of DERP (`O/crates/ts_runtime/src/route_updater.rs:51`). Receive drains `try_recv_from` until WouldBlock (`O/crates/ts_runtime/src/direct.rs:180`)—application batching, not Darwin multi-message syscalls. Runtime starts the direct actor (`O/crates/ts_runtime/src/lib.rs:88`). What it lacks is the **server exit forwarding path**: public config has no advertise/forward/exit fields (`O/src/config.rs:12`), and all accepted inbound routes go to the application stack (`O/crates/ts_runtime/src/route_updater.rs:193`), without a host TCP/UDP forwarder. Track B should reuse its own direct transport rather than porting fork magicsock by assumption.
