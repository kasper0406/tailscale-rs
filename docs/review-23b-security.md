# Review 23b — GeiserX runtime security

**Verdict: reasonable to keep running as an experimental exit for the owner's trusted devices; not a hardened unattended exit. Confidence: moderate for the authorization/host-exposure conclusions, limited for crypto and denial-of-service resistance.** I found no critical vulnerability, general source-IP spoofing bypass, unauthenticated forwarding service, or control-attribute switch that starts a host shell/file server in this runner. There are reachable availability weaknesses and a **high-severity conditional Tailnet Lock bypass**: do not depend on this implementation to protect against compromised control. A compromised own device can also attack availability of the Mac and other peers' direct paths.

Reviewed on 2026-10-13: official `29d87ee17e73`, GeiserX `origin/main` = `3951752dc1ae`, deployed source `ts-exit/main` = `06850529c6df`. Attribution uses `git diff 29d87ee origin/main`; deployment reachability uses HEAD and `RUNBOOK.md` §2. Unless explicitly revision-qualified, references below are **HEAD**, relative to `/Volumes/git/ts-exit/repos/geiserx-tailscale-rs`. This was static source/diff inspection; exploit scenarios were not executed. Only this report was written.

## Findings by severity

### Critical

None identified in the inspected paths.

### High

**H1 — Tailnet Lock can be disabled by control's assertion; cold starts admit peers before verification. Reachable, conditional on relying on Tailnet Lock.**

`ts_control/src/tka.rs:36` defines enabled as a nonempty head and `!disabled`. `ts_runtime/src/control_runner.rs:456` handles the opposite by discarding the chain and setting the enforcement authority to `None` (`:478`), without verifying a disablement secret. A bootstrap reporting no genesis also clears enforcement (`ts_runtime/src/tka_sync.rs:242`, `control_runner.rs:578`). With no authority, `peer_tracker/mod.rs:368` admits every node; an empty trusted-key set also admits all (`:381`). Authority sync is spawned asynchronously (`control_runner.rs:505`), while the netmap continues to publication (`:1894`). The runner disables netmap caching (`examples/exit_node/main.rs:152`); verified-chain persistence is tied to that cache (`control_runner.rs:600`).

**Scenario:** compromised control sends `TKAInfo.Disabled=true`, then includes an attacker-controlled unsigned node with ordinary `UnsignedPeerAPIOnly=false` and a granting ACL. The local signature gate becomes admit-all. Alternatively, after restart, withholding/failing bootstrap leaves a locked tailnet's unsigned peers admitted. This defeats the intended independent signing boundary. Successful sync does reject unsigned/bad signatures (`peer_tracker/mod.rs:389`) and reevaluates existing peers, but does not close these fail-open cases. GeiserX added TKA; official `29d87ee` had no corresponding enforcement, so this is an unsafe new security feature, not a regression from working official TKA enforcement.

### Medium

**M1 — Network receive queues have no memory budget before tunnel verification. Reachable.**

GeiserX's direct transport spawns a receive pump into an unbounded channel (`ts_magicsock/src/sock.rs:3019`, send at `:3037`). It passes opaque datagrams from a known underlay address (`:1631`) before WireGuard authentication. Runtime handoff feeds another unbounded dataplane queue (`ts_runtime/src/direct.rs:701`; `ts_dataplane/src/async_tokio.rs:82`). TSMP disco advertisements have another unbounded sink (`ts_runtime/src/dataplane.rs:268`); HEAD's reliable control/event bus also has an unbounded mailbox (`ts_runtime/src/env.rs:466`).

**Scenario:** a registered peer establishes a direct path, then sends datagrams faster than the serial decrypt/filter consumer can drain them. Even invalid WireGuard datagrams consume queue memory, regardless of its internet ACL. Valid TSMP advertisements can additionally flood the event path ahead of ACL matching. Sustained overload can cause memory pressure/OOM and lose the remote exit. The direct pump is fork-added; the underlying unbounded dataplane queues already existed in official code. Bounded netstack ingress does not bound these earlier queues. No sustained-flood reproduction was run.

**M2 — Half-open TCP sockets escape the global splice budget. Reachable.**

The all-port gate permits 1,024 active ports (`ts_forwarder/src/all_port.rs:62`, `port_gate.rs:115`). Each TCP listener permits 128 queued handshakes/accepts (`ts_netstack_smoltcp_core/src/config.rs:106`, `socket_impl/tcp/listener.rs:305`, `:393`) and creates a replacement listening socket (`:341`). Every socket eagerly allocates both configured TCP buffers (`socket_impl/tcp/mod.rs:13`, `:35`), default 256 KiB each (`config.rs:102`). The global 2,048-splice limit applies after accept (`ts_forwarder/src/tcp.rs:59`), not before half-open allocation.

**Scenario:** an exit-authorized device sends distinct SYN tuples across many public destination ports, keeping handshakes pending. The theoretical TCP backlog allocation approaches **64 GiB**, plus listening sockets, despite the splice cap. This is allocation capacity, not a measured RSS figure; lazy zero pages and timeouts affect actual residency. Completing/filling many connections can still cause substantial Mac memory pressure. Fork-added forwarding expands a per-listener resource bound into this aggregate exposure. Keepalive/reaping and port limits prevent indefinite unrestricted socket counts, but provide no Mac-sized global buffer budget.

**M3 — A peer can claim another peer's disco key through TSMP and disrupt direct-path attribution. Reachable without an internet ACL.**

WireGuard/source-attributed TSMP disco advertisements are consumed before ACLs (`ts_dataplane/src/lib.rs:1097`). `ts_runtime/src/peer_tracker/mod.rs:1238` checks zero/unknown/unchanged keys, then installs the supplied public key (`:1263`) without rejecting ownership collisions. `peer_tracker/peer_db.rs:170` overwrites the disco-key index; lookup uses the last writer (`:301`). The direct verifier subsequently compares that indexed node key to the claimed node key (`ts_runtime/src/direct.rs:526`, `:535`).

**Scenario:** admitted peer A advertises peer B's public disco key. B's next direct Ping resolves to A and fails the node-key binding test; shared disco-key path state can also be misattributed. A need not possess B's disco private key to overwrite the index. DERP fallback may preserve B's connectivity, but direct service can be disrupted. WireGuard decryption and source filtering still prevent A from decrypting B's traffic or spoofing B's overlay source. This peer-driven mutation is fork-added.

**M4 — Taildrop and Funnel substitute membership for specific capability authorization. Compiled, dormant in this runner.**

Taildrop checks configured storage, the receiving node's `file-sharing` attribute, and source membership; it does **not** check the sender's `file-send` grant (`ts_runtime/src/peerapi.rs:424`). Funnel ingress accepts any known node rather than a specifically authorized ingress relay (`:459`, `:470`), once a local Funnel sink exists (`:513`). Its downstream pump also spawns TLS tasks without a concurrency limit/handshake timeout (`ts_runtime/src/funnel.rs:162`).

**Scenario if locally enabled:** a peer allowed to connect to peerAPI uploads files despite lacking a send grant, or impersonates an ingress relay and opens many stalled TLS sessions. The runner has `taildrop_dir=None` (`src/config.rs:756`) and never calls `listen_funnel`; the absent sink returns 404 (`peerapi.rs:517`). Control node attributes alone cannot supply storage or install that sink. These are new compiled surfaces, not current file-write/shell exposure.

### Low

**L1 — Documented build command does not select the requested AEAD feature. Deployment uncertainty.** `runner/build.sh:6` (workspace root) invokes Cargo without `--features ring-aead`; `Cargo.toml:338` declares the opt-in feature. Existing release fingerprints contain both tunnel variants. Thus the script does not establish that the running binary uses ring transport AEAD. Both implementations were inspected; this is not evidence of broken encryption. Binary provenance/live feature selection remains unverified.

## Security checks and deployment limits

| Area | Result and evidence |
|---|---|
| Inbound ordering and spoofing | WireGuard identifies the decrypting peer, then source-prefix lookup must equal that peer (`ts_dataplane/src/lib.rs:1719`, `:1754`); ACL evaluation follows (`:1779`), then inbound routing. `src_filter.rs:57` uses the same installed routes as outbound routing. Runner `accept_routes=false`, no selected exit peer (`src/config.rs:725`), so another peer cannot claim arbitrary routed/subnet sources. Forwarder and app use separate overlay transports, after this common gate (`ts_runtime/src/lib.rs:216`; `route_updater.rs:424`). |
| ACL exceptions / capabilities | Non-SYN TCP, recognized ICMP replies, cached UDP/SCTP replies, later fragments, and TSMP have explicit accept cases (`ts_dataplane/src/lib.rs:512`, `:589`, `:608`, `:630`). They are exceptions inside the filter stage, after source attribution, not alternative unfiltered listeners. Capability-based source rules receive an empty capability set (`:675`): restrictive failure, not an allow-all. The filter compiler rejects ACLs granting `UnsignedPeerAPIOnly` sources (`ts_runtime/src/packetfilter.rs:134`, `:207`). Established flows are not freshly authorized on every packet. |
| Exit destination protection | TCP and UDP HostExit dialing check forbidden destinations (`ts_forwarder/src/dialer.rs:163`, `:170`, `:359`): loopback, RFC1918, link-local/metadata `169.254.169.254`, CGNAT, multicast/broadcast, 0/8, 240/4, and all IPv6. Flow class comes from local configured routes (`class.rs:46`), so control's self route list alone cannot make the host dial an unconfigured private subnet. The runner advertises only default routes. This is an address-range guard: public-address hairpin services/publicly numbered LANs are not excluded. |
| Proxy behavior | No proxy in runner defaults (`src/config.rs:735`). When selected locally, failed TCP proxy handshakes return errors, with no direct fallback (`ts_forwarder/src/dialer.rs:337`, `:403`); proxy UDP is refused (`:416`). `forwarder_actor.rs:126` selects the dialer from local configuration. |
| DNS / open resolver | peerAPI listens on the overlay netstack, not a Mac TCP socket (`ts_runtime/src/peerapi.rs:110`). Its DNS handler requires a current known peer and an ACL-granted TCP-SYN probe to internet port 53 (`peerapi_doh.rs:430`), plus common Host/Origin/Referer validation (`peerapi.rs:197`, `:382`). It is not a public open resolver. Headers, DoH bodies and request concurrency are bounded (`peerapi.rs:65`, `:75`; `peerapi_doh.rs:107`); requests time out (`peerapi.rs:147`). Lack of a packet-level peerAPI carve-out is stricter than the L7-only design described in the fork. |
| DNS host exceptions | **Our branch adds deliberate host DNS access**: private-destination port 53 is redirected to the operator resolver (`ts_forwarder/src/dialer.rs:206`); peerAPI recursive DNS uses host UDP/TCP when `exit_node_dns` is set (`ts_runtime/src/peerapi_doh.rs:495`, `:523`). It actually dials the upstream selected from control DNS configuration (`magic_dns.rs:726`), so a configured split resolver can be on the LAN/loopback or a nonstandard port. The runner supplies a resolver by default (`examples/exit_node/main.rs:126`). Consequently “never reaches LAN” has a DNS exception, and this path trusts control's resolver destinations. This host-forwarding addition is ours, not attributed to GeiserX. Also do not combine it with proxy-origin privacy assumptions: the peerAPI host DNS hop bypasses the proxy dialer. |
| UDP bounds | 512 flows per port; global 2,048 UDP flows; permits acquired before host dial; connected destination sockets, 65,535-byte receive cap, idle reaping at 30 s DNS / 120 s other traffic (`ts_forwarder/src/udp.rs:23`, `:38`, `:47`, `:132`, `:146`, `:215`; `all_port.rs:92`). Replies can refresh idle time, but cannot exceed the flow-count budget. |
| Host services and bindings | SSH/russh is feature-gated and absent (`src/lib.rs:213`; `Cargo.toml` feature `ssh`). FFI/Elixir/Python are separate workspace packages, not dependencies of this example. Serve/Funnel/Taildrop handlers are compiled; their managers/storage require local calls/config (`src/lib.rs:403`, `:1951`, `:2015`; `ts_runtime/src/env.rs:453`). Control-delivered SSH policy or file/Funnel capabilities cannot start them. C2N exposes echo/VIP metadata; remote LocalAPI requires a local handler and `remote_config=true`, both absent (`src/config.rs:754`; `ts_control/src/tokio/ping.rs:157`, `:209`). Unknown debug paths return an error (`:178`). Packet capture requires installing a local hook (`ts_runtime/src/dataplane.rs:239`); runner installs none. |
| Tunnel crypto | No authentication downgrade found in changed handshake/transport code. Initiations reject equal/older timestamps (`ts_tunnel/src/endpoint.rs:748`); tentative responder sessions expire (`handshake.rs:548`). Replay window grows from official's 192 to 8,128 counters (`replay.rs:126`); replay state advances only after AEAD success (`session.rs:353`, `:362`). Send nonces are reserved under a mutex and stop at exhaustion (`session.rs:113`); rekey/reject limits include message count (`:266`). Ring failure drops/wipes candidate plaintext (`transport_aead.rs:61`). Handshake secrets and input key buffers are zeroized (`handshake.rs:39`; `transport_aead.rs:29`), but complete erasure of ring's opaque expanded key is not established. HEAD fixes the inherited official/GeiserX key-replacement session-retention defect (`endpoint.rs:1041`); it is not an active finding here. |
| Cookies and disco | Official rejected all nonzero mac2; GeiserX accepts mac1 and checks cookies under load (`ts_tunnel/src/macs.rs:273`; `endpoint.rs:1249`). This is not a handshake-authentication bypass: Noise still authenticates the static peer key. Cookies bind to attributed peer IDs rather than raw socket addresses; direct input drops unknown source addresses (`ts_magicsock/src/sock.rs:1638`). Disco still uses authenticated SalsaBox (`ts_disco_protocol/src/packet.rs:191`); runtime checks key/node binding. Candidate caps and address guards constrain learned probes (`ts_magicsock/src/disco.rs:43`; `path.rs:171`; `sock.rs:693`). M3 is the remaining attribution weakness found. |
| TLS / Noise | DERP uses normal certificate verification or exact SHA-256 leaf pinning (`ts_derp/src/dial.rs:57`, `:81`; `ts_tls_util/src/pinned.rs:104`). `InsecureForTests` requires disabled `insecure-derp` / `insecure-for-tests` features (`ts_control/src/derp.rs:60`). Control key fetch defaults to HTTPS, then Noise IK targets that server key (`ts_control/src/tokio/connect.rs:161`, `:199`; `ts_control_noise/src/handshake.rs:45`). No reachable TLS-verification bypass found in the requested feature graph. |
| Panics / disk writes | No demonstrated ordinary-peer malformed-packet panic found. Duplicate node keys from malformed **control** maps can still panic (`ts_tunnel/src/endpoint.rs:1032`, `:1075`; `peer_tracker/peer_db.rs:129`); the original official tunnel also panicked on collisions. Fixed-size crypto unwraps and listener invariants were inspected, not exhaustively proved. Runner state writes target its configured key file (`examples/exit_node/main.rs:115`); logs/PID are in the state directory. No enabled peer-driven arbitrary file write found. Taildrop storage, netmap/TKA caching and certificate persistence require local configuration; the runner leaves them disabled. |

HEAD uses guaranteed delivery and startup barriers for security subscribers (`ts_runtime/src/env.rs:466`; `lib.rs:193`, `:298`). The official/GeiserX best-effort update-loss concern in the existing runbook is therefore **historical for this HEAD**, although queued ACL/peer changes remain asynchronous and existing-flow exceptions remain. This review does not claim atomic revocation.

## Out of scope / unchecked

No code, branch, daemon, ACL or control state was changed. No builds, fuzzing, adversarial network tests, live feature/binary verification, Mac memory measurements, or full cryptographic audit were performed. Findings are source-derived. Dependency vulnerabilities/supply chain (Review 23a), excluded SSH/binding/TUN/ACME implementations, complete Serve/Taildrop filesystem semantics, vendored smoltcp correctness, and every fork-added module were not exhaustively audited. Actual tailnet policy, Tailnet Lock enablement, host resolver configuration, public-IP hairpin behavior, OS firewall and restart supervision were not inspected. The verdict assumes control is trusted for ordinary netmaps/ACLs and the permitted devices remain trusted; H1 specifically invalidates using Tailnet Lock to remove that control trust.
