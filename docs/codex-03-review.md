**Recommendation:** retain paired advertisement, the ingress IPv6 rejection, the HostExitDialer boundary and the nonblocking pipe fix. ## Ranked findings

1. **P1, pre-existing security blocker: changed/expired identities still retain tunnel authority.** `ts_tunnel/src/endpoint.rs:1028–1038` swaps config without shutting down sessions, pending handshakes or the old key's MAC sender. `ts_runtime/src/dataplane.rs:466–487` also upserts an expired node; `ts_control/src/node.rs:501–508` retains its source/outbound routes. Source checking still identifies the old session as that same PeerId, so this is reachable for a peer retaining old session secrets. Fix: validate collisions first, remove/recreate the peer on static-key or PSK change, remove expired peers rather than upserting, and exclude expired nodes in the common route predicate. Task B implements this. Reliable security-state delivery is still required: `ts_runtime/src/env.rs:451,504` retains the baseline default bus and asynchronous registration. See the lossless/snapshot design in `codex-02-ipv6.md`; this series does not fix blocker 5.

2. **P1, introduced lifecycle regression: cancelling the gated manager does not cancel its listeners.** `ts_forwarder/src/all_port.rs:274,290–310` detaches each JoinHandle and stores a plain AbortHandle; dropping an AbortHandle does not abort. The raw manager instead owns `PortEntry` with an aborting Drop (`:91–102`). Cancelling `Forwarder::run` aborts its JoinSet child, the manager (`ts_forwarder/src/forwarder.rs:159–166`), but leaves the manager's children and independent readiness waiters running. They retain channels/dialers; a standalone cancelled forwarder can continue accepting/dialing while its netstack is alive. Fix: own listener tasks in a JoinSet or an abort-on-drop owner, track readiness without a detached child, and abort/join all listener tasks on exit. Existing detached **TCP splice** tasks (`ts_forwarder/src/tcp.rs:91`) are an additional baseline shutdown limitation; decide whether shutdown must cancel active splices too.

3. **P2, introduced race: Ready/Exited identify a port, not a listener generation.** Events at `ts_forwarder/src/all_port.rs:269–272,316–319` and gate operations at `ts_forwarder/src/port_gate.rs:168,184` have no generation check. A listener can send readiness and then return; its detached readiness waiter can report Ready after Exited. If another ingress has reopened the port in between, old Ready releases the new SYN before the new listener exists. Conversely, a queued old Exited processed after reap/reopen removes the new AbortHandle and closes the new slot. The listener's current natural-error exits often coincide with netstack teardown; these are state-machine defects, **not a demonstrated remote cap-bypass exploit**. Two deterministic probes against c49d946 fail the desired invariants: [probe patch](../scratch/codex-03-gate-regressions.patch), [output](../scratch/codex-03-gate-regressions.log). Fix: monotonically increasing generation in Slot, OpenRequest, manager entry and every event; conditionally operate only on that generation. A stale exit must neither remove the current owner nor decrement its active count.

4. **P2, introduced race: reaping is neither an atomic idle claim nor completed teardown.** `PortGate::idle_ports` snapshots idle slots under the lock (`port_gate.rs:197–209`), then the manager unconditionally closes them under a new lock (`all_port.rs:323–328`). Ingress can refresh `last` or pass a new SYN between those operations; the refreshed port is still killed. `close` also publishes Closed before `abort()` has completed or the old socket's asynchronous close has been applied, so a new opening overlaps old socket teardown. Fix: `claim_idle(now, idle)` atomically rechecks freshness and transitions to **Closing**, with generation; abort/join and acknowledge socket unregistration before publishing Closed/releasing a new generation. Test using paused barriers between idle selection, fresh ingress, abort completion and a new SYN. Simply reversing `close`/`abort` is insufficient.

5. **P2, introduced lifecycle wedge: manager closure condition is unreachable; Opening is never reaped.** The manager itself owns a gate (`all_port.rs:262`); that gate owns the request sender (`port_gate.rs:74`). Thus `requests.recv()==None` cannot mean “every gate handle is gone” as claimed at `all_port.rs:281–283`. No netstack-close branch exists. A panicking/cancelled listener also bypasses the terminal send at `:308`; its slot stays Opening forever, whereas idle selection considers only Open (`port_gate.rs:204`). Ordinary **bind errors do send Exited**, drop held packets and free the slot; there is no permanent bind-error wedge on that ordinary path. Fix: explicit shutdown/closed signal, JoinSet completion including JoinError, and bounded Opening deadline; release accounting through the generation-aware close path exactly once. Test a failing bind, panic before Ready, loss of all external gate handles, and netstack closure.

6. **P2, remaining policy gap: the host destination guard is a static special-address denylist.** `ts_forwarder/src/dialer.rs:163,170,181–185,300–331` correctly refuses ExitNode flows to RFC1918, loopback, link-local, CGNAT/tailnet, multicast and all IPv6 before opening a socket. Subnet flows intentionally bypass that guard; explicit narrower advertised routes classify as Subnet (`ts_forwarder/src/class.rs:41–48`), so their ACLs must be audited separately. A LAN using globally routable addresses is not excluded. Go subtracts **local interface prefixes** from default-route admission and re-adds the host's own addresses (`repos/tailscale-go/ipn/ipnlocal/local.go:3704–3727`); connecting to an exit host's own public IP is allowed there. Fix for general Go parity: include interface-route exclusions with explicit semantics for host IPs, and validate actual control-expanded `autogroup:internet` rules. For this Mac's RFC1918 home LAN the new guard addresses the immediate boundary; do not describe it as complete Go parity. `exit_node_allow_lan_access=false` in the example (`examples/exit_node/main.rs:98`) is a **client routing preference**, not server-side protection.

7. **P2/P3, remaining UDP lifetime bug: P3 is absent from this series.** Flow idle refresh is still ingress-only (`ts_forwarder/src/udp.rs:100,167,182`); reply pump `:203–209` does not stamp it. A continuing receive-only flow is reaped 30–45 seconds after its last outbound datagram. Gate port freshness is also ingress-only (`port_gate.rs:138`), so fixing just the flow clock still leaves a 120–180 second port eviction aborting UDP mappings. Fix both levels: shared last-activity stamp refreshed on replies, or keep a port alive while it owns live flows. Existing TCP splices survive listener eviction because their tasks are detached, which is a separate shutdown concern.

## Checks that hold, and performance qualifications

* **Lock/order/accounting:** ingress, flush and close use the same synchronous mutex (`port_gate.rs:129,169,185`), with no await under it. A successful held enqueue precedes subsequent ingress; no ordinary lock-order deadlock found. Opening increments once (`:155`), close decrements once and is idempotent while Closed (`:186–193`). Bounds are 1024 combined TCP/UDP slots, 32 held packets per port, 1 MiB held total (`all_port.rs:59`; `port_gate.rs:45,48,71`). Raw mode had separate per-protocol port managers; the combined cap is a capacity change. These invariants require the generation fix above to mean “live listener count.”
* **Cold packets can still be lost under pressure:** `mark_open` removes the whole held queue and ignores each `try_send` result (`port_gate.rs:173–178`). Queue saturation loses initial SYNs/UDP again and `released` overstates delivery. This is bounded overload behavior, not an ACL bypass. Count failures; for a stronger cold-packet guarantee, keep unsent packets in a bounded draining state and retry on queue readiness without allowing later ingress to overtake. Pre-opening common ports remains a useful optional latency/cap-pressure optimization. Fragmented IPv4 packets bypass the gate (`:249`), so a cold fragmented datagram is not protected. Gate classification also checks lengths, not checksums (`:248–259`), permitting admitted malformed traffic to consume the bounded listener budget; validate before allocation if this becomes a practical DoS seam.
* **IPv6 runtime boundary is sound:** every dedicated forwarder ingress packet passes the version check and unconditional consume at `ts_runtime/src/forwarder_actor.rs:250–265`, before either gated or exact-port ingress and irrespective of Direct/Host/Proxy selection. `enable_ipv6` does not disable that hook. Ordinary valid TCP gets a correctly sequenced RST; ordinary UDP gets bounded ICMPv6 type 1/code 1 (`ts_forwarder/src/ipv6_reject.rs:15–79`). Later/malformed/unsupported fragments deterministically drop; extension-before-fragment TCP can also drop (`:27–31`). There is no promise of a reply for every malformed/fragmented flow. The public standalone Forwarder/PortGate API still needs its embedder to install the hook (PortGate deliberately passes IPv6); no equivalent global invariant is built into those constructors. Locally initiated IPv6 application-netstack traffic is outside this transit hook.
* **Rejection flood risk:** replies bypass the forwarder ingress bound and enqueue into an unbounded channel (`forwarder_actor.rs:253–258`; `ts_runtime/src/dataplane.rs:114–129`). This queue was already unbounded, but the new hook can produce replies without smoltcp ingress throttling. Consider bounded/rate-limited rejection emission; consume IPv6 even when response capacity is exhausted. Source ownership still precedes this path (`ts_dataplane/src/lib.rs:1754–1766`), then packet filtering (`:1779`); non-SYN TCP/later-fragment carve-outs mean “reached the hook” is not proof of an explicit matching ACL. No new unauthorized-peer/forged-source host-egress path was found in the series.
* **Paired advertisement changes no source-family switch:** startup composition (`ts_control/src/config.rs:676–699`) and both live setters' shared composition (`ts_runtime/src/lib.rs:1585–1594`) append the same pair and deduplicate. Explicit IPv6 subnet routes remain filtered. An accepted self `::/0` routes to the forwarder (`ts_runtime/src/route_updater.rs:431–438`); the peer's IPv6 host route remains in source/reply routing independent of `enable_ipv6` (`src_filter.rs:57`; `route_updater.rs:246`). Advertisement alone installs nothing until control returns accepted routes. Peer default-source authority is still limited to the selected exit peer by `Node::routes_to_install`; advertising our own pair does not grant other peers `/0` source ownership. Status remains the baseline **any default route** predicate (`ts_runtime/src/status.rs:170–173`) and suggestions deliberately retain that wider definition (`exit_node_suggest.rs:79–100`), rather than Go's pair test. No need to change it to make this runner selectable by Go; do update those stale “IPv4-only parity” comments later.
* **Nonblocking pipe fix is correct:** `ts_netstack_smoltcp/src/pipe.rs:250–258` retains buffered receive behavior and byte/waker accounting while changing blocking recv to try_recv. Its empty-pipe regression test is useful (`:476`). I agree with unconditional paired advertisement for this runner; my earlier enum was optional API design, not necessary protection.
